# 英文访谈文章SOP与团队约定

## 依据和优先级

本文件为独立可执行的团队规则，整理自深度板块SOP2.1（2025年4月）及已确认的英文访谈编译实践。执行时只依赖本Skill内文件，不要求访问维护者的历史聊天或外部工作区。

本参考保存实质文字规则，并非原指南全部图片示例的复制。用户提供本期模板时优先遵循；缺少视觉示例时不凭空补造规格，按本包明确的格式基线执行。

优先级：当前用户明确要求 > 本期已确认例外 > 本文件团队规则 > 文档技术默认值。本期例外记录在本期QA，不自动改变同事的任务。

团队默认：交付三份Word，由作者导入飞书；封面另计，正文至少四图；优先联网找英文逐字稿，找不到才考虑有授权的转写；使用rules.json中的豆包提示词；署名及声明模板见footer.txt。不自动认领任务、修改状态表或发布文章。

## 标题和作者

- 标题自拟，格式`深度｜xxx`，竖线为全角`｜`。
- 选题关键词、辨识度高的人物/公司/机构、真实核心观点和有意义的数字优先；需要时点明特殊身份。少用“解析”等说教措辞。
- 不把查不到的年龄或心理活动写进标题，不以案例推断全面替代岗位，不把预测、目标、试验写成确定业绩。
- 每期提供三个候选题目并翻译原视频题目，用户选择之前用忠实译题作工作标题。
- 有明确原作者就写人名，没有则写机构或栏目；多人访谈可写机构，如a16z。原作者/访谈机构不同于末尾编译署名，不相互替代。

## 摘要、Highlights、介绍

- 摘要80字以内，用原文精彩发言的忠实译文，用中文引号标识。
- Z Highlights置于正文前，通常2—3点，特别复杂精彩时可到5点。
- 优先原文第一人称金句，可调整语序或合并，不另写第三人称归纳，不使用“XXX认为”“作者表达了”。
- Highlights只对重点部分加粗，不全部加粗也不全无加粗。
- 介绍置于Highlights和正文之间，斜体。人物背景一般50—100字，多人可延长；访谈背景20—50字；注明访谈时间。只知道发布日期时准确标为发布日期，不猜录制时间。
- 不为英文文章模式强加访谈背景。本Skill主要处理访谈，非访谈文章请求应选择对应工作流，不能硬套对话。

## 全文与翻译

- 长篇分段翻译，保持完整；重要案例、数字、逻辑和限定不能因润色消失。
- 从原义组织通顺中文，不机械逐词翻译，不改成摘要或作者议论。检查说话人、代词、否定、时间范围、比较和可能性。
- 无实义的口头禅、卡顿、附和可删；保留开场欢迎、结束感谢和告别。真正的问题、反对或纠正不能作为附和删掉。
- 以主话题分若干大段并添加清楚标题，不按每次发言增添小标题。长回答手动分段。
- 正文为“人物名字：说的话”，中文无时间戳；英文保留真实时间戳，来源没有则说明，不伪造。
- 选10—20处完整核心句加粗。重要句冒号前概括内容一并加粗，不只强调零散关键词。
- 疑点、取证过程、转写不清和审核说明放Word评论，不暴露在观众正文中。敏感内容大幅删减必须取得用户同意。

## 术语与空格

- 人名通常保留英文；特别常见中文译名如李飞飞、黄仁勋、马斯克按习惯。不能把Claude拼成Cloud。
- 保留Agent、Token、Transformer、Diffusion、Computer Use、Coding Agent、Scaling law、RLHF、SWE-bench等适用的术语，不机械译成代理、令牌、变换器或电脑使用。
- 核对GPT-4o、OpenAI、Ilya Sutskever、Dario Amodei、Yann LeCun、Geoffrey Hinton、Yoshua Bengio、Jeff Dean、SSI、Chinchilla等拼写。
- a16z始终小写；DeepSeek、xAI、ReAct、Llama等按官方大小写。MCP可解释为Model Context Protocol（模型上下文协议）。
- cloud是一般概念时译云平台/云服务等，不因Claude名称相近一概保留。open source与open-weight按原文区分，不能混同开源与开放权重。
- 不常见概念可保留英文后加简明中文括号，或用`（ZP注：……）`，解释应帮助普通读者/VCPE理解，不变成扩展评论。
- 中英、中数以及英数排版边界不额外添空格。只删除确认多余的空格，不全局清空英文姓名、固定短语和官方名称内部空格。

## 配图与格式

- 封面一张，有颜色或浅灰背景，不纯白。正文至少四张，封面另计；图片相关、清晰、分散。
- 用官方节目、原文、公司、产品、人物照片/图示；截图不能带无关滚动条、浏览器外框或暴露隐私。不能制造假现场。
- 图注以普通文字写在图片下面，`图片来源：具体出处`，不要只塞进图片“编辑描述”。为核查保留可点击原始来源。
- 如接到论文导读分支，原文所有图片必须按顺序保留，不能只满足四图数量。
- 每段之间实际空行，包括Highlights、标题后、图片、长回答分段。允许的特殊文本格式只有加粗、必要斜体及灰色；不添加引用块、正文序号、彩色装饰、浮动卡片或分割线。
- 正文标题黑色，勿混用Z Wave红色标题。人物介绍和结尾斜体；其他斜体/灰色慎用。
- 字体字号在采集SOP中没有完整硬性数值，以最新指定模板为准；无模板时用rules.json的保守默认值，并检查真实渲染效果。

## 结尾、审核、返修

- 原始链接、编译署名和完整声明必须存在；用`scripts/skill_config.py`解析本期署名并填入`footer.txt`，不得沿用他人署名、残留占位符、删减社群邀请或改写Z Potentials品牌。
- 如另加编译者简介，原SOP要求英文公开名+一句话介绍，需主理人备案；不擅自添加联系方式、简介或备案声明。
- 全文交豆包审查，提示词和结果处理见交付参考。没执行就不能写“经审核无敏感内容”。
- 英文原文另存Word，同时在成品编辑评论给文件入口，不把整段英文长文贴进评论。
- 至少完整通读一次；初稿按可交付标准，不能把必做检查留给用户。
- Mentor意见逐项读、对应修改并回复“已修改”及具体改动；不自行隐藏或解决评论。原SOP要求24小时内返修；Skill不会安排后台定时任务，有期限影响时说明并沟通。
